# 知识库访问与文档生命周期规范

本文为自编演示资料，用于权限、幂等与生命周期检索测试。

## 用户归属

知识库、文档和会话都归属于创建它们的用户。所有对外请求由 Java 校验当前用户，前端提交的 owner_id 不能作为授权依据。用户只能查看和修改自己的资源；未知资源与其他用户资源使用一致的不可访问响应，避免暴露其存在。

## 内部调用

Python 引擎只接受带有效服务密钥的内部请求。Java 在权限校验之后传入 knowledge_base_id 和 allowed_documents。allowed_documents 为空表示当前没有授权文档，绝不能解释为检索全部文档。服务密钥只保存在服务端，不进入前端构建产物。

## 重复上传

同一用户在同一知识库上传内容摘要相同的文件时，应复用已有文档记录。文件名称只用于展示，不用于确定文档身份。索引片段使用 document_id、index_version 和片段序号生成稳定标识，失败重试不会产生重复片段。

## 删除

文档进入 DELETING 状态后应立即从允许检索列表排除。物理清理成功后进入 DELETED，失败则进入 DELETE_FAILED，允许再次重试。业务库与向量库之间没有跨库事务，因此需要明确状态与补偿流程。

## 对话历史

会话消息由 Java 持久化，Python 只接收本次生成需要的历史。流式请求只有在最终消息和引用成功落库后才发送 done。用户取消时记录 CANCELLED 状态，中途失败记录 FAILED，不能把不完整回答标记为成功。
