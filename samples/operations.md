# 知识引擎运行维护规范

本文为自编演示资料，描述本项目的目标运维流程，不代表所有能力已实现。

## 健康检查

存活检查只判断服务进程能否响应，不依赖模型或向量库。就绪检查还需确认必需配置、本地模型目录和向量数据库连接。就绪失败时应从返回的依赖状态定位原因，不能仅凭 HTTP 进程已启动认定系统可用。

## 故障定位

每个请求都有 request_id，Java 入口与 Python 检索日志使用同一标识。定位慢请求时依次检查 embedding、向量检索、HyDE、rerank 和生成阶段耗时。若 HyDE 显著增加延迟而没有改善召回，应先停用该策略再比较。

## 备份

演示环境每天凌晨两点执行一次备份，保留最近七份。备份范围包括 SQL 业务库、原文对象与向量库快照。恢复时先恢复业务元数据，再恢复相同索引版本的向量数据，最后检查文档 READY 状态与实际索引是否一致。

## 模型变更

更换 embedding 模型时必须重建索引，因为新旧模型产生的向量空间不兼容。新索引应使用独立版本，完成评测后再切换，保留旧索引用于回滚。仅更换生成模型不必重新生成文档向量，但仍需验证引用与答案质量。

## 容量告警

磁盘使用率达到 80% 时发出预警，达到 90% 时暂停新文档导入并通知维护人员。优先清理临时解析文件、失败任务产物与过期索引版本，不应删除仍被 READY 文档引用的索引。
